# POLY SCOUT — автоматическое пополнение компаний через GitHub Actions

Этот набор дополняет POLY SCOUT v13. Он **не** содержит новые данные о компаниях и не публикует их, пока вы не добавите файлы в репозиторий и не запустите workflow.

## 1. Загрузите файлы

Откройте репозиторий на GitHub -> вкладка Code -> Add file -> Upload files. Перетащите **содержимое этой папки** (включая скрытую `.github`), сохранив структуру:

```
.github/workflows/update-leads.yml
tools/update_leads.py
tools/test_update.py
data/leads.json
data/leads.js
```

**Важно:** это только дополнительный пакет. Если в репозитории уже есть `data/leads.json`/`data/leads.js` с реальными компаниями, **не перезаписывайте их пустыми примерами** — оставьте существующие версии. Также убедитесь, что в корне есть `index.html`, `assets/app.js` и остальные файлы вашего сайта.

Для загрузки всех файлов и папок можно использовать Git (команды внизу). Если GitHub не принял директории перетаскиванием, создайте их через Add file -> Create new file, вводя полный путь из списка выше.

## 2. Включите GitHub Pages из Actions

Откройте Settings -> Pages -> Build and deployment -> Source -> **GitHub Actions**.

Это важно: commit с `GITHUB_TOKEN` не запускает ещё одну автоматическую публикацию через старый Pages branch workflow. Наш процесс сам публикует сайт после сбора.

## 3. Разрешите запись обновлений

Settings -> Actions -> General -> Workflow permissions -> **Read and write permissions** (если эта настройка доступна). В YAML также указаны нужные права `contents: write`, `pages: write`, `id-token: write`.

## 4. Проверьте первый запуск

Вкладка Actions -> слева **Update public business leads and deploy** -> Run workflow -> Run workflow.

Успешно должны завершиться шаги `Test collector`, `Collect new open data`, `Store updated data in repository`, `Deploy to GitHub Pages`.

Должны обновиться `data/leads.json` и `data/leads.js` (при наличии новых данных). Если Overpass недоступен, сборщик оставит старую базу, а workflow отметит ошибку.

## 5. Проверка на сайте

Обновите опубликованный POLY SCOUT (лучше Ctrl+F5) и нажмите «Обновить список». Вся CRM — заметки, статусы и копия CRM — остаётся в вашем браузере, а GitHub Actions обновляет только публичную общую базу.

## Расписание

`04:23 UTC` ежедневно = `07:23 по Москве`. Каждый день проверяются очередные 6 из 176 городов. Полный круг занимает примерно 30 дней при успешных запусках. На GitHub во вкладке Actions → Update public business leads and deploy → Run workflow можно указать в поле city один город (например, Казань) для внеочередного поиска. Публичный OSM может содержать неполные или устаревшие контакты. Отсутствие тега `website` не означает отсутствия сайта.

GitHub Actions может запускаться с опозданием, а в неактивных публичных репозиториях расписания могут отключаться после 60 дней.

## Возможные причины отсутствия результата

- На Actions виден только `pages build and deployment`: `.github/workflows/update-leads.yml` не загружен в ветку `main` или не активирован.
- В логе `git push` ошибка 403: недостаточные права `contents: write` / Workflow permissions / branch protection.
- `Collect new open data` завершился ошибкой: оба Overpass API недоступны; попробуйте `Run workflow` позже.
- `Deploy to GitHub Pages` ошибка: в Settings -> Pages не выбрано **GitHub Actions** или Pages не включён.
- После успеха ноль новых компаний: OSM может не содержать подходящих организаций с публичными контактами в сегодняшних районах.

## Git с ПК (если через браузер неудобно)

```
git clone https://github.com/krutoi280/POLY-SCOUT.git
cd POLY-SCOUT
# скопируйте в эту папку содержимое POLY_SCOUT_AUTO_FILES, сохраняя подпапки
git add .github/workflows/update-leads.yml tools/update_leads.py tools/test_update.py data/leads.json data/leads.js
git commit -m "Enable daily POLY SCOUT leads collection"
git push
```

Никаких секретных API-ключей не требуется. Скрипт не отправляет сообщения компаниям и не собирает закрытые персональные данные.
