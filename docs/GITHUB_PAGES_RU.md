# Публикация POLY SCOUT на GitHub Pages (Windows)

В проект уже включён workflow `.github/workflows/update-leads.yml`. Он публикует статический сайт через GitHub Actions и по расписанию пытается обновлять базу открытых компаний из OpenStreetMap/Overpass.

## Перед публикацией

1. Распакуйте архив так, чтобы внутри одной папки `POLY_SCOUT_v13` сразу находились `index.html`, `assets`, `data`, `games`, `tools` и `.github`.
2. Откройте `index.html` локально в Chrome/Edge и убедитесь, что главная страница, ферма и аркада открываются.
3. Экспортируйте резервную копию CRM и фермы из прежней версии. Не публикуйте эти резервные копии в репозитории: в CRM могут быть личные заметки и контакты.

## Вариант A — GitHub Desktop (рекомендуется)

1. Войдите на [github.com](https://github.com) и создайте новый пустой репозиторий, например `poly-scout`. Для бесплатного GitHub Pages выберите **Public**. Не добавляйте README, `.gitignore` или лицензию на этапе создания — они уже есть в проекте.
2. Установите и откройте [GitHub Desktop](https://desktop.github.com/), войдите в тот же аккаунт.
3. Выберите **File → Clone repository**, найдите `poly-scout` и клонируйте его в удобную папку, например `C:\Projects\poly-scout`.
4. Скопируйте **содержимое** папки `POLY_SCOUT_v13` из распакованного архива в клонированную папку репозитория. В корне репозитория должен лежать `index.html`, а не ещё одна вложенная папка `POLY_SCOUT_v13`.
5. Убедитесь, что скопировалась скрытая папка `.github`, внутри которой находится `workflows/update-leads.yml`. В Проводнике Windows включите **Вид → Показать → Скрытые элементы**, если не видите `.github`.
6. Вернитесь в GitHub Desktop. Внизу слева введите Summary, например `Publish POLY SCOUT v13`, нажмите **Commit to main**, затем **Push origin**.

## Включить GitHub Pages

1. После создания пустого репозитория откройте его на GitHub.
2. Перейдите в **Settings → Pages**.
3. В блоке **Build and deployment** выберите **Source: GitHub Actions**. Не выбирайте `Deploy from a branch`: проект содержит собственный workflow.
4. Теперь отправьте файлы проекта в ветку `main` через GitHub Desktop. Первый push запускает публикацию.
5. Откройте вкладку **Actions**. Дождитесь завершения workflow **Update public business leads and deploy**.
6. Когда workflow станет зелёным (`Success`), откройте **Settings → Pages** и нажмите **Visit site**.

Адрес проекта обычно выглядит так:

`https://ВАШ-ЛОГИН.github.io/poly-scout/`

Публикация может занять несколько минут. Если workflow не запускается, проверьте, что основная ветка называется `main`, а `.github/workflows/update-leads.yml` находится в корне репозитория по указанному пути.

## Если GitHub Actions не может записать обновлённую базу

Workflow уже запрашивает `contents: write`, `pages: write` и `id-token: write`. Если организация или настройки репозитория ограничивают запись:

1. Откройте **Settings → Actions → General**.
2. Найдите **Workflow permissions**.
3. Если политика аккаунта позволяет, выберите **Read and write permissions** и сохраните.
4. Вернитесь в **Actions**, откройте неудачный запуск и выберите **Re-run all jobs**.

Не добавляйте в публичный репозиторий пароли, токены, резервные копии CRM или личные контакты.

## Как обновляется список компаний

- Кнопка **«Обновить список»** на сайте только загружает уже опубликованный `data/leads.json`. Она не запускает поиск сама.
- При первом push workflow только публикует сайт. После успешной первой публикации запустите сбор вручную через **Actions → Update public business leads and deploy → Run workflow**.
- Затем workflow пытается собрать открытые сведения из OpenStreetMap/Overpass ежедневно по расписанию (cron `23 4 * * *`, то есть 04:23 UTC) и при ручном запуске. За один запуск проверяются три города из списка; полный круг по 45 городам занимает около 15 запусков.
- GitHub может задержать плановый запуск; Overpass может ограничивать запросы или временно не отвечать. Поэтому ежедневное обновление не гарантируется по минутам. Если сборщик не ответит, workflow всё равно опубликует последнюю корректную базу, а ошибку сбора покажет в логах Actions.
- Отсутствие поля `website` в OpenStreetMap означает только, что сайт не указан в этом источнике. Проверяйте компанию, сайт и контакты вручную перед обращением.

## Сохранения и приватность

- CRM, избранное, заметки, статусы и прогресс игр сохраняются в `localStorage` браузера на конкретном устройстве. Они не синхронизируются автоматически между телефоном и ПК и не отправляются в GitHub.
- При использовании одного и того же браузера и домена GitHub Pages локальные данные обычно остаются доступны после обновления файлов. Если меняется домен/аккаунт/браузер или вы переходите с `file://`, импортируйте заранее созданные JSON-копии CRM и фермы.
- Репозиторий и опубликованный GitHub Pages сайт доступны публично, если выбран Public. В `data/leads.json` попадают только публичные сведения из источника; не добавляйте туда личные записи.

## Частые проблемы

- **Открывается README, а не сайт:** проверьте, что `index.html` находится в корне репозитория, а не во вложенной папке.
- **Игра не открывается:** проверьте, что папки `games/farm` и `games/arcade`, а также `games/games.css` и `games/audio.js` скопированы целиком.
- **Обновление списка не находит новые компании:** проверьте статус workflow в Actions. Кнопка на сайте не является поисковым роботом.
- **После обновления пропали заметки:** восстановите резервную копию CRM из JSON в том же браузере и домене.
